# Testing Evidence Overview

Synchro separates the contract from testing evidence.

## What Is Authored

The specification, requirements catalog, support matrix, and scenarios are reviewed source material. They define behavior, proof obligations, required environments, and expected outcomes. They do not contain hand-maintained coverage or release-readiness results.

The support matrix defines PostgreSQL 18 on Ubuntu 24.04 Linux x64. It defines Swift on iOS 16 and current iOS. It defines Kotlin on Android API 24 and current Android. It defines React Native 0.83.x on current iOS and Android. PostgreSQL 14 through 17 are excluded. macOS hosts Swift validation and is not a PostgreSQL support cell.

## What Is Generated

Release records the exact environment, commands, results, replay information, and artifact hashes. `release-manifest.json` records resolved current versions.

Tooling computes release eligibility from that evidence. Documentation, fixture presence, and the current handwritten test inventory do not certify a release.

## Published Metadata Scope

Each release publishes metadata with a narrow scope. Each item below states what it covers and what it does not cover.

- `SHA256SUMS` lists the SHA-256 digest of each release file except itself.
- `release-manifest.json` records the source commit, root Git tree, source tags, workflow runs, resolved support environments, and digests of selected dependency manifest and lock files. These fields identify inputs. They do not make a build reproducible, and a rebuild from the same commit can produce different bytes.
- `sbom.spdx.json` is Syft 1.33.0 SPDX JSON output for the built release components. Release verification requires a SHA-256 file record for each public payload.
- The SBOM package list contains only what Syft detects in those files, for example Go modules in the Linux executables. It is not a complete inventory of Rust, Maven, npm, Swift, or CocoaPods dependencies.
- Each package declares its own dependencies in its POM and Gradle module, `package.json`, `Package.swift`, or podspec.
- GitHub artifact attestations cover each file that `SHA256SUMS` lists. The Release workflow signs them through GitHub OIDC, and the predicate is the release manifest.
- Maven files have detached `.asc` OpenPGP signatures. Release verification checks only that each signature is well-formed ASCII armor with a signature packet. It does not verify a signature against a signer key.
- The npm package has an npm provenance attestation from trusted publishing. Publication requires `npm audit signatures` to report no invalid or missing signature for the exact version.
- The Kotlin POM and Gradle module declare OkHttp and kotlinx-serialization-json as API dependencies, because public signatures expose `OkHttpClient` and `JsonObject`.

To verify an attestation for one downloaded file, run this command:

```sh
gh attestation verify <file> --repo trainstar/synchro \
  --signer-workflow trainstar/synchro/.github/workflows/release.yml \
  --predicate-type https://trainstar.fit/synchro/attestations/release/v1
```

## Evidence Standard

Release-critical proofs use independent expected results, real packaged components for happy paths, meaningful negative controls, and replayable fault or randomized cases. Implementation-derived fixtures and tautological assertions do not establish semantic correctness.

Every required test must run. Skips, ignored tests, unexplained flakes, and retry-only passes block promotion. Reruns remain linked to their original failures with a recorded reason and diagnosis.

The final support gate derives semantic obligations and packaged checks from the support matrix. It rejects missing, skipped, unavailable, malformed, zero-test, and nonterminal results.

Each non-excluded support cell requires packaged connect, push, pull, process-kill, and resume checks. The package installation step must use the release artifact under test.

Each installed client writes a change offline, is killed, and resumes. While the client is dead, the harness writes a new remote value on the server. The cell passes only when the client reads that value through its public query path and PostgreSQL holds the exact resumed write. An empty queue alone does not pass a cell, because rejection or deletion also empties a queue.

The Makefile reads the generated packaged summary from `dist/verification/packaged-smoke-summary.json`. Missing summary data blocks the gate.

Security evidence may be access-controlled while a finding is unresolved. Public reports describe scope and disposition without publishing exploit instructions.

## Release Procedure

Release builds final distributions once. Package checks and publication use the same sealed bytes.
