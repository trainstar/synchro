# Synchro v0.3.0 Phase 1-5 Audit

Date: 2026-08-21.
Scope: commits `37ad227..540c843` plus the uncommitted worktree, approximately 185,000 committed and 48,000 uncommitted lines.
Method: seven independent parallel reviews across the conformance harness, gates and CI, the server extension, the Go adapter, Swift, Kotlin, and React Native, plus one push and conflict deep review. The primary reviewer re-verified every Critical claim directly before inclusion.

## Verdict

The product code is honest. No reviewer found a fabricated implementation, a hardcoded outcome, or a weakened assertion in production surfaces. The repository contains zero skipped or disabled tests. Test expectations are authored, not captured from production output.

The Phase 5 gate layer contains one integrity breach. Three native conformance Make targets pass green while they execute zero tests, and release evidence includes them. The current worktree does not compile, so no current gate claim is valid. Phase 4 closed its work without the required evidence ledger.

The verification system is genuinely independent and mostly non-gameable, but it is larger than the product it guards. See the companion remediation plan.

## Critical findings

### C1. Vacuous native conformance gates in release evidence

- `Makefile:337-349` runs `go test -run` for `TestNativeSwiftSchemaQueuedMutationPersistsAcrossSIGKILL`, `TestNativeSwiftSteadyPull`, and `TestNativeSwiftRebuildRequests`.
- These functions exist in no commit and not in the worktree. `git log -S` across all refs returns nothing.
- A zero-match `go test -run` exits 0, so each target passes while it executes no test.
- The targets are wired into `release-check` (`Makefile:566`), `.github/workflows/ci.yml:515`, and `.github/workflows/release.yml:350`.
- GitHub issue 35 records these targets as passed. Those claims are not reproducible from any tracked state.

### C2. The worktree does not compile

- `conformance/blackbox/native_controller.go:1991` fails with `undefined: sha256`.
- Every conformance-dependent gate fails on this state. No Phase 3, 4, or 5 gate claim is currently valid.

### C3. React Native Android bridge is missing six declared methods

- `clients/react-native/src/NativeSynchro.ts:144-152` declares `inspectClientState`, `inspectTransportObservations`, `armTransportPause`, `awaitTransportPause`, `resumeTransportPause`, and `getProcessIdentity`.
- iOS implements all six. Android implements none. The checked-in codegen output is stale.
- The next codegen run breaks the Android build. JavaScript parity is broken now.

## High findings

### H1. The authored scenario corpus never runs against the real server

- `conformance/cmd/synchro-conformance/main.go:177` returns "unavailable" for strict black-box execution.
- The real PostgreSQL gate is a separate hand-written `TestReal*` corpus that loads no file from `conformance/scenarios/server/`.
- The two proof paths can drift silently.

### H2. The commit-order negative control proves harness bookkeeping

- The server checks are real (`extensions/synchro-pg/src/bgworker.rs:2248-2257` and `validate_progress_order` at `bgworker.rs:2639`).
- The scenario blocked-step verdict comes from the controller's in-memory map (`conformance/blackbox/native_controller.go:1444-1449`).
- No curated mutant targets `validate_progress_order`. A mutant that deletes the server check would likely survive every gate.

### H3. Phase 4 has no evidence ledger

- Issue 34 requires documented S-01 through S-28 dispositions before Phase 5 starts. It has zero comments.
- The Phase 4 work itself is largely real. The ledger must be reconstructed before any release-candidate claim.

### H4. Client gates omit required suites

- `make test-kotlin` filters to two Robolectric classes. No target runs the Android instrumentation obligations.
- `test-kotlin-unit` and the React Native unit suite are absent from `release-check` and the workflows.
- `phase-5-check` does not exist. `test-client-platforms` runs one cell and nothing invokes it.
- No gate parses results for skips outside the mutation path, so the zero-skip policy is unenforced.

### H5. Server hot paths conflict with the performance goal

- Steady-state pull recomputes full scope digests on every poll, at cost proportional to all rows in all subscribed scopes (`extensions/synchro-pg/src/pull.rs:1295-1378`).
- WAL materialization issues about six to eight sequential SPI statements per row (`bgworker.rs:3087` and `bgworker.rs:4236`).

### H6. Client hot paths conflict with the performance goal

- Swift apply rebuilds and recompiles identical SQL per row and runs a per-row protected-check query (`clients/swift/Sources/Synchro/PullProcessor.swift:346-389` and `901-949`).
- Kotlin revalidates the complete CDC trigger set on every application write (`clients/kotlin/synchro/src/main/kotlin/com/trainstar/synchro/SynchroDatabase.kt:989-1079`).

### H7. A protocol-parsing proxy ships in the production React Native Android artifact

- `clients/react-native/android/src/main/kotlin/com/trainstar/synchro/rn/TransportObservationProxy.kt` parses sync wire bodies in the main source set.
- `SynchroModule.kt:152-168` silently reroutes the SDK server URL through it.

## Medium findings

- Cross-engine `Retry-After` drift. Kotlin accepts strict delta-seconds or RFC-1123 dates and blocks otherwise. Swift accepts any `Double`-parsable value. One engine retries where the other blocks.
- Scope-removal delivery is untested. The prior positive test for non-empty `scope_updates.remove` was deleted. All surviving assertions are emptiness-only. This is the only weakening-class change found.
- Dead `synchro-core` modules are presented as remediated findings. `dedup.rs`, `state.rs`, most of `version.rs`, and `limits.rs` functions have no production consumer.
- The Go adapter fails open on a codeless error envelope and returns HTTP 200 (`api/go/errors.go:30-61` and `api/go/handlers.go:62-66`).
- The retention scenario writes internal `synchro.sync_clients` metadata directly (`conformance/blackbox/push_retention_controls.go:106-121`).
- Kotlin has a `debounceJob` data race, test-only schema paths that bypass the migration journal, and an unreachable `RETRY_EXHAUSTED` mapping.
- React Native has a grep-based parity test that missed C3, strict DTO parsing that throws inside event callbacks, and a committed regenerated `seed.db`.
- `extensions/.cargo/mutants.toml` contains an undocumented equivalent-mutant exclusion.
- React Native iOS validation runs nightly only and does not block pull requests.

## Additional findings

These lower-severity findings complete the reviewer reports. Each one carries a task in the remediation plan.

- The Go operator package reads extension-internal tables directly and encodes recovery branching in Go (`api/go/operator/operator.go:597,674,797,824,857-881`).
- The operator discards underlying error causes without `%w` wrapping (`operator.go:161,265,274,306`).
- The seeddb generator holds a third hand-maintained copy of the client SQLite DDL with no cross-surface identity check (`api/go/seeddb/seeddb.go:1550-2168`).
- Pull performs per-entry registry and schema loads (`pull.rs:734,1060,1235`).
- Pull takes a whole-request `SHARE MODE` lock on `sync_wal_progress` and serializes against materialization (`pull.rs:70`).
- Every pull runs an unbounded changelog malformation scan per scope (`pull.rs:753-791`).
- Each WAL transaction pays three or more extra acknowledgment transactions (`bgworker.rs:2265-2278`).
- Worker memory per source transaction is unbounded because the full transaction buffers before decode.
- No restart test exists between materialization and slot advancement.
- The sealed-intent ledger content for `schema_incompatible` outcomes has no direct assertion.
- No pg test proves portable-seed snapshot isolation under concurrent source writes.
- The wire-visible SemVer strictness change needs a recorded decision.
- The React Native conformance runner can reuse a leftover database in `create` mode across relaunches, and `unavailable` outcomes must never read as skips.
- Verification-only inspection and transport-pause APIs sit on the public Swift and React Native clients.
- Kotlin has a lifecycle lock-order hazard for calls made inside an application transaction, and a concurrent second `stop()` can return before `Stopped` publishes.
- Duplicated helpers exist across the Rust extension, the React Native runner, and Swift processors.
- Swift engine tests include sleep-based negative assertions with flake risk.
- Pass-through gate variables are not recorded in generated evidence.
- The application SQL limitations are undocumented for client developers.
- Mocked happy-path engine proofs duplicate flows the real scenario corpus must own.
- The evidence signing scheme is self-attested with an in-process key.

## Strengths to preserve

- The dual-implementation digest system with authored vectors, invalid vectors, and count guards.
- The integration mutation gate with baseline-pass, mutant-fail, and post-baseline-pass discipline.
- The Swift SQLite authorizer and the Kotlin SQL-lexer write boundary for `_synchro_*` state.
- Durable-identity retry on both engines. The exact request JSON is the work identity.
- The Android conformance harness with real process kill and death confirmation.
- Packaged consumer proofs that reject workspace resolution.
- Fail-closed defaults across gates, environment handling, and poison states.
